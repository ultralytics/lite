# AGENTS.md

This file provides guidance to AI coding agents (Claude Code, etc.) when working with code in this repository. CLAUDE.md is a symlink to this file.

Ultralytics Lite (AGPL-3.0) is a local-only desktop workspace for Claude Code, Codex, Gemini CLI, Kimi Code, Qwen Code, and shell sessions. It keeps agent sessions, files, and Git context in one window without repository indexing, telemetry, or a cloud service. It is built with Tauri 2, Rust, React 19, TypeScript, Tailwind CSS 4, and shadcn's Nova style with Base UI. The app version lives only in `src-tauri/Cargo.toml` (`version = "0.0.50"`); `package.json` and `tauri.conf.json` carry none, and bumping it on `main` is what publishes a release (see Workflows).

## Core Principles (CRITICAL)

**Less is more. The simplest solution is the best solution.** The action hierarchy for every change: **Delete > Replace > Add**.

1. **Solve at the owner**: Put behavior in the code path that owns or observes it. For fixes, never guard a symptom with a staleness check, initialization flag, skip-first-call branch, or `try/except` around broken logic; relocate the trigger and delete the wrong path. For features, extend the existing owner rather than creating a parallel abstraction.
2. **Search and reuse first**: Search the whole repository before creating a feature, component, helper, workflow, or utility. Reuse or adapt what exists, consolidate in-scope duplication in the shared owner, and delete duplicate paths. Three similar lines beat a helper nobody else calls.
3. **Delete and modify existing code before creating new code**: Bugfixes are net-negative by default unless deletion and relocation are demonstrably impossible. A new file must first prove it cannot fit cleanly in an existing owner.
4. **Keep scope minimal**: Implement only the simplest complete solution. Avoid impossible-state handling, speculative flags, compatibility shims, policy scaffolding, and unrelated cleanup. Tests are out of scope by default — rely on existing coverage and focused validation; only an uncovered, high-risk regression path justifies minimal new test code.
5. **Ship zero-regression, production-ready changes**: Understand what you remove instead of retaining broken code as insurance. Remove unused imports, functions, types, files, and comments; run relevant cleanup checks; and thoroughly debug and validate the changed owner. Do not break existing features or workflows unless the PR intentionally removes them with evidence.

**Review gate:** for every addition, the reviewer decides whether deleting or changing existing code would have fixed the problem instead — if it would, that is a blocking finding. A missing or thin PR description is never itself a finding.

NEVER push to `main`. NEVER force push. Always start work in a new git worktree (`git worktree add`) on a feature branch and open a PR — never edit the primary checkout directly, it may hold in-flight work.

Repo-specific rules that sharpen these principles here:

- **Stay quiet**: no indexing, file watchers, telemetry, cloud service, or idle background work. Read files, Git state, and provider usage only on explicit user interaction, and bound file and terminal memory.
- **Providers own their sign-in**: never read, copy, or proxy a CLI's credential store. A key the user hands to Lite is Lite's to keep — owner-only in the app data folder, handed to a session through the provider's environment variable, never written into provider configuration.
- **Launch through the user's PATH**: a launched app inherits a bare PATH and the PATH given to a child does not locate the program, so resolve provider CLIs against the login shell's PATH and run them by full path.
- **Platform behavior lives in Rust** and the interface stays platform-neutral, so macOS, Windows, and Linux share one codebase.
- **Use the generated components in `src/components/ui/`** rather than local lookalikes, and verify their Tailwind variants against the attributes Base UI actually emits — `data-orientation` is not `data-vertical`, and a wrong variant fails silently and reads as a styling mistake.
- **Lazy-load terminal and file-rendering dependencies**, and measure startup bundle changes before accepting new UI libraries.
- **Keep the React contract camel-cased through Serde**, and remember every `Option` field arrives as `null` rather than as a missing key.

## PR Workflow

After opening a PR:

1. Wait for the automated PR review and auto-format commit from Ultralytics Actions (`format.yml`), then pull and address every finding.
2. Review the full diff in-session against the Core Principles, performance, and the review gate above, then batch the fixes into one commit and push. After each round of bot or human commits, pull and resume the same reviewer on `<last-reviewed-sha>..HEAD` plus anything that delta could have invalidated. Repeat until the local head matches the live head.
3. Hand off or merge only on a clean final pass: one cold full-diff review returning LGTM with no findings, on a head that is still live at merge time.
4. Never fight other commits: Ultralytics Actions pushes auto-format and header commits, and multiple users may work on the same PR. `git pull --rebase` before pushing; never reset or revert commits you did not author.
5. After the PR merges, clean up: remove local worktrees and branches for it, then `git checkout main && git pull`.

## Commands

Prerequisites: Bun >= 1.3.14 (`engines`/`packageManager` in `package.json`), a stable Rust toolchain with `rustfmt` (the crate is `edition = "2024"` and uses let-chains, so keep it current), and the Tauri 2 platform prerequisites (Linux CI installs `libwebkit2gtk-4.1-dev libappindicator3-dev librsvg2-dev patchelf`).

```bash
bun install                      # Also applies patches/ to @xterm/xterm (package.json "patchedDependencies")
bun run tauri dev                # Desktop app: runs `bun run dev` (Vite on port 1420, strictPort) then the Rust shell
bun run check                    # bun run lint && bun run typecheck && bun run deadcode
bun run lint                     # biome check . --diagnostic-level=error
bun run typecheck                # tsgo --noEmit (native TypeScript preview compiler)
bun run deadcode                 # knip (config: the "knip" block in package.json)
bun run format                   # biome check --write .  (TS/TSX/JS/JSON; CSS formatting is disabled in biome.json)
bun test                         # Frontend unit tests in tests/*.test.ts (bun:test)
bun test tests/shortcuts.test.ts # One file; filter by name with `bun test -t "<pattern>"`
cargo fmt --check --manifest-path src-tauri/Cargo.toml
cargo test --manifest-path src-tauri/Cargo.toml # Rust unit tests: `mod tests` at the bottom of src-tauri/src/lib.rs
cargo check --manifest-path src-tauri/Cargo.toml
bun run build                           # tsgo --noEmit && vite build → dist/ (both index.html and splash.html entries)
bun run tauri build --debug --no-bundle # What CI runs: compile and link, no installers
bun run tauri build                     # Native installer for the current operating system
bun run local                           # "Lite Dev" app (identifier com.ultralytics.lite.dev, red icons, its own app data folder)
```

CI (`.github/workflows/ci.yml`, matrix `macos-latest`/`ubuntu-latest`/`windows-latest`, on PRs and `main` pushes) runs `bun ci` → `bun run check` → `bun test` → `cargo fmt --check` → `cargo test` → `bun run tauri build --debug --no-bundle`. Lint failures fail CI, so run `bun run check` and `cargo fmt` locally before pushing. Biome (`biome.json`) enforces double quotes, semicolons, 120-column lines, the `recommended` rules with `noDangerouslySetInnerHtml` and `noArrayIndexKey` off, and relaxes a11y rules only under `src/components/ui/**`; it skips gitignored paths (`vcs.useIgnoreFile`).

## Workflows (`.github/workflows/`)

- `ci.yml` — the check matrix above. Never packs installers (bundling cost more than everything else combined).
- `format.yml` — Ultralytics Actions on PR open/synchronize/close and new issues: Prettier for YAML/JSON/Markdown/CSS, codespell spelling, Lychee link check, AI labels and PR summary. It pushes auto-format commits to the PR branch (`python: false`, so no Python tooling runs). Biome is not part of it; format TS/TSX yourself with `bun run format`.
- `publish.yml` — on every push to `main`: reads the version from `src-tauri/Cargo.toml` via `cargo metadata`; if no published release `v<version>` exists, creates a draft release with generated notes, builds installers with `tauri-apps/tauri-action` (macOS `aarch64-apple-darwin` dmg+app, Ubuntu 22.04 `x86_64` AppImage, Windows `x86_64` NSIS) signed with `TAURI_SIGNING_PRIVATE_KEY`, generates an SPDX SBOM with Syft, injects the notes into the updater `latest.json`, verifies the exact asset set (`Lite_<v>_darwin_aarch64.app.tar.gz`, `.dmg`, `Lite_<v>_linux_amd64.AppImage`, `Lite_<v>_windows_x64-setup.exe`, `latest.json`, `sbom.spdx.json`), then publishes. Feature PRs that ship a release carry the version in the title, e.g. `Fix terminal zoom latency across sessions (0.0.50)`.
- `dependencies.yml` — daily 06:00 UTC: `bun update --latest` plus `cargo update`, opens an "Auto-update dependencies" PR, waits for checks, squash-merges with `--admin`. It crosses semver ranges; version ceilings belong in the root `overrides` block of `package.json` (currently `@codemirror/view` at `6.43.8`), which survives `--latest`.
- `cla.yml` — Ultralytics CLA check on PRs. `dependabot.yml` bumps GitHub Actions weekly.

## Architecture

Startup: Tauri opens two windows from `src-tauri/tauri.conf.json` — `splash` (`splash.html`, always on top) and `main` (`index.html`, `visible: false`). `src/main.tsx` applies the stored theme, stamps `data-titlebar="overlay"` on `<html>` on macOS (the top bar reserves room for the traffic lights), and renders `App`. `App`'s first effect invokes `startup_ready`, which shows and focuses `main` and closes `splash`. The Rust entry `src-tauri/src/main.rs` also doubles as Claude Code's status-line and hook binary (`--claude-statusline`, `--claude-activity`) before falling through to `lite_lib::run()`.

Session flow: `App.tsx` `launch()` creates a `Channel<ArrayBuffer>` and calls `invoke("spawn_session", …)`. Rust `spawn_session` resolves the workspace grant (`Roots`), decides whether to resume, builds the harness command (`agent_command`), opens a PTY with `portable-pty`, and streams raw output bytes over the channel from a reader thread; on exit it emits `pty-exit {sessionId, runId}`. The frontend's `receiveOutput` feeds `appendOutput` (`src/output-store.ts`), which buffers up to `MAX_OUTPUT_BYTES` (1,000,000) per session and parses OSC title/cwd/activity/bell sequences; the mounted `TerminalView` subscribes to the same store, so inactive tabs keep history without an xterm instance. Keystrokes go back through `writeSession` → `invoke("write_session")` on a per-session promise queue. Every Tauri command lives in `src-tauri/src/lib.rs` and is registered in the `tauri::generate_handler![…]` list inside `run()`; the frontend calls them by snake_case name with camelCase arguments (Tauri converts), and every Serde payload struct is `#[serde(rename_all = "camelCase")]`.

Bridge conventions: commands return `Result<T, String>`; the frontend shows the string. Filesystem and process work runs under `tauri::async_runtime::spawn_blocking`. Events emitted by Rust: `pty-exit`, `shell-agent` (`{sessionId, runId, agent|null}` from `watch_shell_agent`), `update-progress` (percent), `notification-clicked`. Every per-session event carries a `runId` and the frontend ignores events whose run id does not match `runs.current` — a new event needs one too. Platform-only commands are `#[cfg]`-gated on both the function and its `generate_handler!` entry (see `write_clipboard`).

### Rust (`src-tauri/`)

`Cargo.toml` (crate `lite`, lib `lite_lib`; deps: `tauri`, `tauri-plugin-updater`, `tauri-plugin-dialog`, `portable-pty`, `sysinfo`, `reqwest`+`rustls`, `tungstenite`, `atomicwrites`, `toml_edit`, `uuid`; macOS `objc2*`, Linux `dbus`, Windows `windows`). `build.rs` stamps `LITE_DATE` (last commit date) and, outside GitHub Actions, `LITE_COMMIT` and `LITE_REPO` so a local build can name and refresh itself. `capabilities/default.json` grants the `main` window `core:default` plus window destroy/start-dragging/is-fullscreen; the CSP is in `tauri.conf.json`. `src-tauri/gen/` and `target/` are gitignored build output.

`src/lib.rs` is one file (~6.5k lines). Landmarks, top to bottom:

- Constants: `MAX_FILE_BYTES` 500,000, `MAX_IMAGE_BYTES` 10,000,000, `DIRECTORY_PAGE_SIZE` 250, `MAX_GIT_CHANGES` 500, `MAX_GIT_DIFF_BYTES` 1,000,000, `MAX_SSH_OUTPUT_BYTES`, `SSH_COMMAND_TIMEOUT` 30 s, `CODEX_REQUEST_TIMEOUT` 20 s, `DEEPSEEK_MODEL`, `CODEX_NOTIFICATION_ARGS` (forces `osc9` notifications and a `session-id | thread` terminal title), `SUPPORTED_KEYS` (`claude codex deepseek openrouter gemini kimi`), `CODEX_PROVIDERS` (DeepSeek and OpenRouter: base URL, env key, model, setup URL).
- Managed state (`.manage()` in `run()`): `Sessions` (session id → `PtySession` with child, master, shared writer, output channel, `run_id`, `alive`, `agent_watch`), `Roots` (grant id → `WorkspaceRoot::Local(PathBuf) | Ssh(SshRoot)`), `ProviderSessions` (Lite session id → provider conversation id), `CodexServer`, `FileBrowserSettings`, `WakeLock`, `PendingNotification`, `Installer`.
- App data (`app.path().app_data_dir()`, keyed by the bundle identifier, so `bun run local` gets its own): `roots.json`, `provider-sessions/<session-uuid>` (one file each), `worktrees/<grant-id>` (`WorktreeRecord`), `api-keys.json` (created `0o600` by `write_api_keys`), `last-directory`, `hide-hidden-files` (presence is the flag), `claude-<session>.json` (generated Claude `--settings`), `usage-<session>.json`, `activity-<session>/<run-id>/`. Writes go through `write_atomic` (`atomicwrites`). `delete_session_data` removes the per-session files.
- PATH: `user_path()` caches the login shell's PATH once (`shell_path` runs `$SHELL -lic`, falling back to `/bin/sh`); `refresh_user_path()` after a CLI install (Windows reads the user PATH through PowerShell); `resolve_executable(name)` searches it; every child gets `PATH` set explicitly. `git` and `gh` are resolved the same way.
- Provider homes: `provider_home_parts` honors `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, `GEMINI_CLI_HOME`, `KIMI_CODE_HOME`, `QWEN_HOME` with `~/.claude`, `~/.codex`, `~/.gemini`, `~/.kimi-code`, `~/.qwen` fallbacks. `cli_auth` only checks presence (macOS keychain item `Claude Code-credentials`, Codex `auth.json`, Gemini/Qwen `oauth_creds.json`, Kimi `credentials/kimi-code.json` or `kimi provider list`).
- Claude integration: `claude_settings()` writes a per-session settings file whose `statusLine` command and `SubagentStart`/`SubagentStop` hooks call the Lite executable (`capture_claude_status` writes `usage-<session>.json` and prints the `\x1b]6973;lite-working|idle\x07` OSC the frontend reads; `capture_claude_activity` tracks subagents as files under `activity-<session>/<run-id>/`). `claude_launch_id` resolves a `/resume`d conversation by scanning `projects/*/<id>.jsonl` transcripts.
- Launch: `spawn_session` → `agent_command(app, &SessionCommand)`: `session_arguments` (Claude/Gemini/Qwen `--session-id <id>` or `--resume <id>`, Kimi `--session <id>`), Codex `CODEX_NOTIFICATION_ARGS` + per-launch `-c model_provider=…`/`model=…`/`model_providers.<id>.*` overrides for DeepSeek/OpenRouter (a user-authored `<provider>.config.toml` profile wins via `--profile`; `deepseek_catalog` appends the DeepSeek model to Codex's bundled catalog), then `codex_resume_arguments` (`resume <thread>`); shell sessions use `CommandBuilder::new_default_prog()`. `login_command` for `mode: "login"`; `mode: "rebuild"` runs `git pull --ff-only origin main && bun run local` and prints `lite-rebuild-finished`. `configure_session_command` sets `TERM=xterm-256color`, `LC_CTYPE=UTF-8` on macOS, and `COLORFGBG`; `api_key_env`/`saved_api_key` inject the provider variable (`ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, `DEEPSEEK_API_KEY`, `OPENROUTER_API_KEY`, `GEMINI_API_KEY` + `GEMINI_DEFAULT_AUTH_TYPE`, `MOONSHOT_API_KEY`). If the same session id is still running (page reload), `spawn_session` swaps the output channel and returns instead of respawning.
- Session identity: Codex thread ids arrive through the terminal title (`record_codex_session`, validated against `codex_thread_ids` from the app server); Kimi ids are discovered by polling `kimi_current_session` with exponential backoff; Gemini/Qwen transcripts are located by `native_session_path`; `codex_thread_resumable`/`kimi_session_ids`/`claude_launch_id` drop a stale `provider_session_id` so a deleted conversation starts fresh instead of failing. `update_provider_session` claims an id for exactly one tab.
- Codex app server: `ensure_codex_server` spawns `codex app-server --listen unix://` (socket `$CODEX_HOME/app-server-control/app-server-control.sock`; `ws://127.0.0.1:<port>` on Windows) and `codex_requests` speaks JSON-RPC (`initialize`, `thread/list`, `thread/read`, `account/rateLimits/read`, `account/usage/read`) for `read_usage` and session validation. `stop_runtime` kills it and every PTY on exit and before an update installs.
- Files and Git (all scoped to a grant): `scoped_path` canonicalizes and requires `starts_with(root)`; `scoped_entry` deletes a symlink itself, not its target. `list_directory` (hidden-file filter, paged), `read_text_file` (rejects >500 KB, NUL bytes, non-UTF-8; `baseline` = the HEAD blob via `git cat-file --filters`), `read_image_file`, `write_text_file` (fails if the file on disk no longer equals `original`, preserves permissions), `delete_entry`. `git_status` runs `status --porcelain=v1 -z --no-renames --untracked-files=all` scoped to the root plus `diff --numstat` against `git_diff_base` (HEAD, or the empty tree when unborn); `git_diff` for one relative path; `git_remote` → `browse_url` (https form only). SSH roots run the same operations through `ssh_stream`/`ssh_output`/`scoped_ssh_script` over `ssh -tt`; Lite-managed Codex providers are local-only.
- Worktrees: `directory_probe` → `main_checkout` + `next_worktree` (sibling folder `<checkout>-worktree-<n>`, branch `lite/worktree-<n>`); `create_worktree`/`create_worktree_inner` records a `WorktreeRecord` and marks the admin dir with a `lite` file; `worktree_state` answers the close dialog; `remove_worktree` refuses anything without Lite's marks (`repo_mark_present`); `restore_worktree`, `forget_worktree`, `undo_worktree`.
- GitHub items: `github_items` → `check_github_items` batches up to 100 references into one GraphQL call through the user's `gh` (never reads its token).
- Availability and installs: `agent_availability`, `install_agent` (Claude/Kimi via their `install.sh`/`install.ps1`, Codex/Gemini/Qwen via `npm install -g`; one at a time through `Installer`, cancellable with `cancel_install`), `agent_update_available` (`--version` vs registry/latest endpoints), `open_setup_docs`.
- Platform: `PlatformWakeLock` (IOKit `IOPMAssertionCreateWithName` / Win32 `PowerCreateRequest`+`PowerSetRequest` / D-Bus `org.freedesktop.ScreenSaver`) behind `set_keep_awake`; macOS-only user notifications via `objc2-user-notifications` (`send_notification`, `notification_session`, `NotificationDelegate` emits `notification-clicked`), `set_attention_badge`, `write_clipboard`, `describe_app` (About panel). `watch_shell_agent` uses `sysinfo` to follow a harness a shell tab launched.
- Updates: `check_update` (10 s timeout, `version_comparator` keeps an equal version so release notes still load), `install_update` (`download_and_install` with `update-progress`, then `app.restart()`), updater endpoint and `pubkey` in `tauri.conf.json`; local builds expose `local_commit`, `local_repo`, `build_date`, `local_update` (fetches `origin/main`), `grant_repo`.

### Harnesses and providers

A harness runs a session and a model provider bills it: Claude Code, Codex, Gemini CLI, Kimi Code, Qwen Code, and the shell are harnesses; OpenAI, DeepSeek, and OpenRouter are providers on the Codex harness. Keep provider-specific behavior behind the existing Rust commands.

## Gotchas

- **The xterm patch is load-bearing.** `patches/@xterm%2Fxterm@6.0.0.patch` changes `Viewport.ts`/`Buffer.ts` sources _and_ the built `lib/xterm.mjs`, and switches the package `main` to the ESM build so `bun test` can import it. `@xterm/xterm` is pinned exactly to `6.0.0` for that reason; bumping it means regenerating the patch (`bun patch`) and re-running `tests/terminal-resize.test.ts`. `bun install` must have run before `bun test`.
- **Version bump = release.** Any push to `main` whose `Cargo.toml` version has no published `v<version>` release publishes installers. Bump deliberately, in the PR that ships the change, and keep `Cargo.lock` in sync (its `lite` entry carries the same version; a `cargo check` updates it).
- **Output is a channel, not an event.** Session bytes arrive through the `Channel` passed to `spawn_session`; a Vite HMR reload of `App.tsx` re-invokes `spawn_session`, which reattaches to the still-running PTY rather than respawning. Do not route terminal bytes through `emit`.
- **Stale-run guards everywhere.** `runs.current` maps session id → `runId`; `pty-exit`, `shell-agent`, and channel messages for another run are dropped. Any new async result about a session must be checked against it before touching state.
- **Private OSC 6973 must stay in sync** between the Rust emitters (`capture_claude_status`, the rebuild command) and the `METADATA` regex in `output-store.ts`; the "output activity" test in `tests/github-items.test.ts` pins the parsing.
- **Codex identity depends on the title.** `CODEX_NOTIFICATION_ARGS` sets `tui.terminal_title=["session-id","thread"]`; `receiveOutput` recognizes the `<hex-id> | <name>` shape and calls `record_codex_session`. Removing or reordering those args breaks resume.
- **Claude settings are generated per launch.** `claude_settings` rewrites `claude-<session>.json` (status line + hooks pointing at the current Lite executable) on every spawn and wipes `activity-<session>/`. Remote (SSH) Claude gets only `{"preferredNotifChannel":"iterm2"}`.
- **`write_text_file` is a compare-and-swap.** It refuses when the bytes on disk differ from `original`; the editor must send the exact contents it loaded (`FilesPanel` does). The same rule holds over SSH (`cmp -s`).
- **Grants, not paths.** Every file/Git command takes a `rootId` from `Roots`; a path outside the grant is rejected by `scoped_path`, and `revoke_directory` is called for grants the dialog abandons. A worktree session's grant may point at a folder that has moved — use `WorktreeRecord.path`, as `worktree_state` does.
- **PATH is cached once per process** (`path_cache`); only `refresh_user_path` (after `install_agent`) updates it. A CLI installed outside Lite is found after a restart.
- **`bun run local` is a different app** (`com.ultralytics.lite.dev`): separate app data, red icons from `src-tauri/icons/dev/`, `createUpdaterArtifacts: false`, and its "update" is `local_update` + a rebuild shell session, not the GitHub updater. Only builds made outside GitHub Actions carry `LITE_COMMIT`/`LITE_REPO`.
- **Base UI attributes**: variants must target what Base UI emits (`data-orientation`, `data-open`, `data-checked`, `data-side`); `src/components/ui/scroll-area.tsx` documents the `data-orientation` case. Tailwind `dark:` is the `.dark` class on `<html>` (`@custom-variant`), not `prefers-color-scheme`.
- **Bundle discipline**: `TerminalView`, `CodePreview`, `SourceEditor`, `FileIcon`, and release-notes Markdown are all `lazy()`; keep new heavy dependencies behind the same boundaries. `vite.config.ts` keeps the icon theme's SVGs as files on purpose.
- **Biome skips CSS formatting, and knip needs `ignoreDependencies`** for `@fontsource-variable/geist` (used only from `index.css` and `splash.html`). Add any similarly CSS-only dependency there rather than through a JS import.
- **Prettier on the bot, Biome locally.** `format.yml` reformats Markdown/YAML/JSON/CSS on the PR; TS/TSX formatting is your job (`bun run format`) and a Biome error fails `bun run check` in CI.
- **Windows differences** live in `#[cfg(windows)]` blocks: `shell_quote`, `refresh_user_path`, `resolve_executable` (`.exe/.cmd/.bat`), the rebuild command (`cmd /C`), the Codex app server over `ws://`. Check both branches when touching them; CI builds on all three platforms.

## Tests

- `tests/*.test.ts` run with `bun test` (no DOM; `tests/shortcuts.test.ts` stubs `globalThis.localStorage` before importing `src/shortcuts.tsx`, which reads it at module load). `tests/github-items.test.ts` covers reference extraction plus `appendOutput` activity parsing; `tests/terminal-resize.test.ts` exercises the patched xterm resize behavior with real `Terminal` instances.
- Rust tests are the `mod tests` block at the end of `src-tauri/src/lib.rs` (`cargo test --manifest-path src-tauri/Cargo.toml`): session locale env, SSH root paths, `scoped_entry`/`remove_entry`, Git status/diff parsing against temporary repositories (some `#[cfg(unix)]`/`#[cfg(target_os = "linux")]`). They spawn the real `git`.
- CI runs both suites on macOS, Ubuntu, and Windows; there is no E2E or Playwright layer. Manual verification is `bun run tauri dev` (or `bun run local` for a persistent dev install) against real provider CLIs.
